# PatchPilot MVP

## Why

PatchPilot 为开发者提供异步 AI 代码审查：提交一段 unified diff，稍后查看结构化问题、严重级别、行号和修改建议。项目也需要用可运行的实现展示需求拆解、接口设计、Prompt 迭代，以及并发和中间件的工程实践。

本变更交付一个可在本地启动的 MVP，默认技术栈为 Java 21、Spring Boot、Vue 3、PostgreSQL、RabbitMQ 和 Redis。后端采用可替换的 OpenAI 兼容模型客户端；自动化测试默认使用确定性的替身，不依赖外部模型凭证。

## What Changes

包含：

- 用户在 Vue 页面提交标题和 unified diff，浏览审查任务列表、状态和结构化结果。
- Spring Boot REST API 提供创建、列表、详情和 findings 查询，并以 OpenAPI 文件维护接口合同。
- PostgreSQL 保存请求、状态、结果和事务发件箱；RabbitMQ 承载异步任务；消费者支持有界并发、重试和重复消息幂等处理。
- Redis 实现提交接口的分布式限流；HTTP 中间件提供请求关联 ID、输入校验和统一错误响应。
- Prompt 以不可变版本保存，审查记录标注使用的版本；小型标注样例集支持 V1/V2 离线回归和可选的真实模型评估。
- Docker Compose 启动应用所需的本地依赖，README 说明配置、启动、检查和数据发送至外部模型的边界。

## Out of Scope

- GitHub/GitLab OAuth、Webhook、仓库安装或自动拉取代码；首版由用户手动提交 diff。
- 多租户、用户认证、团队权限、计费、生产部署和管理后台。首版只面向本机或受信任的开发环境，不应暴露到公网。
- 自动执行代码、自动应用补丁、完整静态分析器或对任意仓库进行全量扫描。
- 锁定某家模型服务。真实模型通过 OpenAI 兼容协议配置；没有凭证时使用开发替身。

## Acceptance Criteria

1. 本地启动后，用户可提交有效 diff，看到 `QUEUED -> RUNNING -> COMPLETED` 状态及 findings；无效、过大或重复提交有可预测的 API 响应。
2. REST 契约覆盖创建、分页列表、详情、分页 findings 和健康检查；错误响应包含稳定错误码与 `traceId`。
3. 数据库与发件箱在同一事务提交；RabbitMQ 不可用时已接受任务仍可投递；重复投递不会重复保存结果或重复推进终态。
4. 消费者并发和预取有配置上限；Redis 限制创建请求速率；请求关联 ID 出现在响应和日志上下文中。
5. Prompt 有至少两个可追溯版本和固定评估样例；离线评估可复现并输出版本对比，真实模型评估不把凭证写入仓库或日志。
6. Vue 页面覆盖提交、列表、状态刷新、详情与 findings；关键状态有明确的加载、空、失败和限流反馈。
7. 每个实现阶段完成其针对性测试；最终通过后端测试、前端测试/构建、Compose 配置检查和本地端到端验证。

## Impact and Risks

- diff 会保存在 PostgreSQL，并在真实模型模式下发送给配置的外部模型服务；界面和文档必须清楚说明这一点。日志不得记录 diff、模型凭证或完整模型响应。
- LLM 输出有非确定性且可能包含错误结论。结果标注为建议，不替代人工审查；后端校验输出结构并拒绝或重试不可解析的响应。
- 过大的 diff 会增加成本和上下文截断风险。首版设置明确字节上限，超限返回 413，不静默裁剪。
- 无认证的首版只适用于本地/受信任环境。Redis 限流降低误用风险，但不构成访问控制。
- 发件箱、重试和幂等处理会增加状态复杂度；生命周期、重复消息和故障恢复必须由集成测试覆盖。

## Stage Boundaries

本计划以可独立验证的项目骨架、同步 API 与持久化、异步链路与中间件、Prompt/模型适配、前端工作流、端到端验证为顺序阶段。每个任务的证明命令通过后再进入依赖它的任务；不在一个阶段一次性生成全部应用。
